# Syllogeum visual retrieval

The benchmark checks the published DINOv2 obverse and reverse vectors from [Syllogeum v1.1](https://syllogeum.org/data/files/syllogeum-open-v1.1/manifest.json). It searches the ANS subset with known catalog types and numeric collection accessions. Every calibration and test accession and every exact image key associated with them is excluded from the reference gallery. Gallery duplicates are removed by accession and image key. Same physical coins with distinct institutional identities or recropped images cannot be ruled out by this check.

The visibly worn cohort was selected from the public photos before running the ranking. The labels record visible relief loss and incomplete peripheral detail, without assigning numismatic grades. The look-alike cohort contains types with a different indexed type from the same authority, denomination and mint. All 122 test coins with a type present in the gallery met that proxy for a look-alike.

The evaluator compares an obverse query against either indexed side and compares two sides in their best alignment. Each type receives the best similarity over its remaining reference specimens. The confidence score adds the winning type’s lead over the runner-up to its similarity. The calibration rule accepts the most correct suggestions while observing zero incorrect suggestions on the separate calibration set.

```sh
python -m pip install numpy==2.5.4
python benchmarks/syllogeum-open/evaluate.py VECTORS_DIR sightings.csv.gz \
  benchmarks/syllogeum-open/queries.json benchmarks/syllogeum-open/wear-labels.json results.json
```

The test used 66,640 distinct reference accessions, 226 calibration coins and 165 test coins. The full report contains ranked type IDs per query. This measures retrieval from released archive vectors. Photo preprocessing and running the query encoder on an iPhone or iPad require a separate test.

## Rerank the two-sided shortlist with OCR

The fusion experiment uses the same specimen splits and gallery exclusions. It takes the 20 visually closest catalog types and matches independently extracted OCR fragments against their published inscriptions in `AncientCoins.json` and `ExpandedCatalog.sqlite`. The candidate URIs connect the visual shortlist to catalog entries. The query’s type, title and curated inscriptions are absent from the OCR input. Matching uses fragments of at least five letters, discounts fragments shared by most shortlisted types, and tests both photo orders. The existing calibration rule sets separate visual and fusion thresholds before scoring test coins.

On Windows with the `en-US` OCR language installed, run the following from the repository root. Files generated by the run go under `DATA_DIR`. The source archive needs its two DINOv2 `.npz` files and `sightings.csv.gz` as above.

```powershell
python -m pip install numpy==2.5.4 Pillow==13.0.0
$data = 'DATA_DIR'
$bench = 'benchmarks/syllogeum-open'
$pack = 'ios/NumiAgent/OfflineCatalog'
python "$bench/evaluate.py" $data "$data/sightings.csv.gz" "$bench/queries.json" "$bench/wear-labels.json" "$data/shortlist20.json" --shortlist-size 20
python "$bench/prepare_ocr.py" "$data/shortlist20.json" "$data/ocr"
powershell.exe -NoProfile -File "$bench/read_ocr.ps1" "$data/ocr/inputs" "$data/ocr/windows-en-US.json"
python "$bench/fuse_ocr.py" "$data/shortlist20.json" "$data/ocr/windows-en-US.json" $pack "$data/ocr/fusion-results.json"
python "$bench/prepare_ocr.py" "$data/shortlist20.json" "$data/ocr-rim" --originals "$data/ocr/originals" --unwrap-rim
powershell.exe -NoProfile -File "$bench/read_ocr.ps1" "$data/ocr-rim/inputs" "$data/ocr-rim/windows-en-US.json"
python "$bench/fuse_ocr.py" "$data/shortlist20.json" "$data/ocr-rim/windows-en-US.json" $pack "$data/ocr-rim/fusion-results.json"
```

Each extraction pass reads both photographs at four orientations and records SHA-256 hashes of the originals. These are low-resolution archive photographs of ancient coins. The run uses Windows OCR. Apple Vision and full-resolution collector photos require separate verification. This tests whether OCR can move a candidate higher within the visual shortlist. A type absent from that shortlist still goes to review.

### Results

The median original image had a 175-pixel long edge. On the 165 test coins, the full image pass emitted text on seven coins. Unwrapping the rim yielded text on 15, with five-letter anchors on three. Neither pass found a discriminating match in the shortlisted catalog inscriptions. The [results summary](fusion-results-summary.json) records both runs.

| Test cohort | Coins | Correct first, all methods | Correct in top three, all methods |
| --- | ---: | ---: | ---: |
| All test coins | 165 | 43 | 70 |
| Worn | 21 | 7 | 11 |
| Look-alikes | 122 | 43 | 70 |

Both methods abstained on every test coin at the zero-error calibration rule. The two-sided shortlist contained the correct type for 106 test coins. Both OCR passes left the rankings unchanged. There is no observed gain from this fusion on these photos.
